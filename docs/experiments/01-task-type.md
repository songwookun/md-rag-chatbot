## 0. 왜 이 실험을 했나

기존 RAG 챗봇(`md-rag-chatbot`)은 100% 바이브코딩으로 만들었다. 코드에 이런 주석이 있다.

**"실측"이라고 적혀 있지만 측정한 사람이 없다.** AI가 쓴 주석이다.
파이썬 백엔드로 이관하면서, 코드에 박힌 이런 숫자들을 하나씩 직접 재보기로 했다.

## 1. 실험 설계

**가설**
- H1: 문서와 질문을 다른 `task_type`으로 임베딩하면 관련/무관 분리도가 커진다
- H0: 차이 없음 → 분기는 불필요한 복잡도

**측정 지표 — 분리도**

| 지표 | 정의 |
|---|---|
| 관련평균 | 질문 ↔ 정답노트 유사도 평균 |
| 무관평균 | 질문 ↔ 정답 아닌 노트 유사도 평균 |
| **분리도** | **관련평균 − 무관평균** ← 핵심 |
| 겹침 | 관련최저 < 무관최고 이면 True |

> **절대 점수가 높은 게 좋은 게 아니다.** 관련 0.9 / 무관 0.88이면 점수는 높아도 못 가른다.
> 벌어지는 정도가 전부다.

**데이터** — 실제 볼트 노트 20개, 질문 22개 (관련 쌍 25 / 무관 쌍 415)

질문 유형을 일부러 섞었다.

| 유형 | 개수 | 의도 |
|---|---|---|
| 제목직격 | 6 | 베이스라인 |
| 본문세부 | 8 | 제목엔 없고 본문에만 → 성능이 갈리는 지점 |
| 복수정답 | 2 | 여러 노트 종합 |
| 유사노트 | 3 | 중복 노트 문제를 일부러 노출 |
| 정답없음 | 3 | abstention 검증 |

## 2. 코드 — 무엇을 왜 그렇게 짰나

> **정리 형식**: 각 함수마다 `무엇 / 왜 / 내가 틀린 것 / 재사용 패턴` 4칸.
> 코드를 통째로 붙이는 건 의미 없다. 판단과 실수만 남긴다.

### ① `cosine()` — 유사도 계산

```python
def cosine(a, b):
    np_a, np_b = np.array(a), np.array(b)
    dot_product = np.dot(np_a, np_b)
    norm_a, norm_b = np.linalg.norm(np_a), np.linalg.norm(np_b)
    return float(dot_product / (norm_a * norm_b))
```

**무엇** — 두 벡터가 얼마나 같은 방향인지를 −1~1로.

**왜 길이로 나누나** — 내적만 쓰면 긴 문서가 무조건 유리해진다. 벡터 성분이 크면 내적도 커지니까. 그런데 길다고 관련 있는 건 아니다. **크기를 지우고 방향만 남긴다.**

검산으로 확인:
```
[1,1] vs [5,5] → 0.99999...  # 크기 5배 차이인데 유사도 1.0
```
볼트에 47,813자 노트와 401자 노트가 같이 있다. 이 정규화 덕에 같은 기준으로 비교된다.

**내가 틀린 것**
```python
dot.product = np.dot(...)   # 점(.)
cosine_similarity = dot_product / ...   # 밑줄(_)
```
→ `NameError: name 'dot' is not defined`

**`dot_product`가 없다고 안 하고 `dot`이 없다고 한다.** 파이썬이 `dot.product = x`를 "변수 선언"이 아니라 "`dot` 객체의 `product` 속성에 대입"으로 읽기 때문. **`.`은 소속, `_`는 이름의 일부.**

**재사용 패턴** — `float()`로 감싸 반환. numpy는 `np.float64`를 주는데 pandas에 넣으면 지저분해진다.

### ② `load_pairs()` — jsonl 읽기

```python
with open(path, "r", encoding="utf-8") as f:
    for line in f:
        line = line.strip()
        if line:
            pairs.append(json.loads(line))
```

**무엇** — 한 줄 = JSON 객체 하나인 `.jsonl`을 dict 리스트로.

**왜 jsonl인가** — 일반 JSON 배열과 달리 **한 줄씩 독립**이다. 끝에 한 줄만 덧붙이면 되고, 파일이 커도 한 줄씩 흘려 읽을 수 있다. 로그·데이터셋의 표준.

**왜 `for line in f`** — `f.read()`나 `f.readlines()`는 전부 메모리에 올린다. 파일 객체를 직접 순회하면 파이썬이 한 줄씩 흘려준다.

**함정 두 개**
- `json.load` vs `json.loads` — 전자는 **파일 객체**, 후자는 **문자열**. 여기선 줄 하나가 문자열이라 `loads`.
- 빈 줄 — 파일 끝 개행 때문에 `""`이 딸려온다. `json.loads("")`는 `JSONDecodeError`. `if line:`으로 거른다.

**재사용 패턴** — `encoding="utf-8"` 명시. 안 쓰면 OS 기본값을 따라가서 Windows에서 한글이 깨진다.

### ③ `fetch_all_notes()` — GitHub API

**무엇** — 볼트의 `.md` 20개를 `{경로: 본문}`으로.

**왜 2단계인가** — GitHub Contents API는 폴더 조회 시 **파일 목록만** 주고 내용은 안 준다. 폴더 3회 + 파일 20회 = 23요청.

**핵심 — `Accept` 헤더**
```python
{"Authorization": f"Bearer {TOKEN}"}                          # 목록용
{**headers, "Accept": "application/vnd.github.raw"}           # 본문용
```
기본은 본문이 **base64**로 온다. `raw`를 주면 원문 그대로 → `resp.text`가 곧 본문.

**왜 404를 에러로 안 보나** — `projects` 폴더가 아직 없는 볼트도 있다. "실패"가 아니라 "아직 없음"이다. `continue`로 넘긴다.

**개선한 것** — `resp.status_code == 200` 대신 `resp.raise_for_status()`.
200만 보면 201·204에서 오작동하고, 무엇보다 **상태 코드가 담긴 예외가 자동으로 올라온다.** 나중에 401/403/404를 구분해 사용자 안내 문구를 만들려면 이 예외가 필요하다.
단, `404 → continue`를 `raise_for_status()` **앞에** 둬야 한다.

**놓쳤던 것** — `httpx.Client()`의 기본 timeout은 **5초**. 긴 노트에서 `ReadTimeout`이 날 수 있다. `timeout=30` 지정.
(`timeout=None`은 더 나쁘다 — 영원히 기다린다.)

### ④ `embed()` — Gemini 임베딩

```python
config = types.EmbedContentConfig(task_type=task_type) if task_type else None
for i in range(0, len(texts), batch_size):
    resp = client.models.embed_content(model=..., contents=texts[i:i+batch_size], config=config)
    embeddings.extend([e.values for e in resp.embeddings])
```

**왜 `config` 분기** — 조합 B는 `task_type=None`이다. `EmbedContentConfig(task_type=None)`을 넘기면 SDK 처리가 불확실하니, **아예 config를 안 보내는 것**이 "기본값" 조건을 정확히 재현하는 방법.

**왜 `extend`, `append` 아님** — `append`는 리스트를 원소 하나로 넣어 `[[v,v],[v,v]]` 중첩이 된다. `extend`는 펼쳐 이어붙인다.

**판단한 것** — `config`를 루프 **밖**으로. 매 배치마다 같은 객체를 새로 만들 이유가 없다.

**틀린 예상** — "47,813자 노트가 토큰 상한에 걸릴 것"이라 예상하고 자르기 로직을 준비했는데, **51,000자까지 그냥 통과했다.** 불필요한 방어였다.

### ⑤ `run_combo()` — 여기서 크게 틀렸다

**무엇** — 조합 하나를 돌려 440쌍의 유사도를 DataFrame으로.

**내가 짠 것**
```python
for question, question_vector in question_vector_map.items():
    for note_path, note_vector in note_vector_map.items():
        is_relevant = note_path in pair["relevant_paths"]   # pair가 없다
```

**왜 틀렸나 — 단순 오타가 아니라 루프 대상 선택 실수**

`question_vector_map`은 `{질문문자열: 벡터}`다. **벡터밖에 없다.** 그 질문의 정답이 뭔지(`relevant_paths`), 유형이 뭔지(`kind`)는 담겨 있지 않다. 그래서 `pair`를 쓰고 싶어도 가져올 데가 없었다.

**고친 것 — 라벨을 들고 있는 쪽을 돈다**
```python
for pair in pairs:                                    # pairs가 라벨을 갖고 있다
    question_vector = question_vector_map[pair["question"]]   # 맵은 '조회'만
```

**배운 것 — dict의 두 가지 역할**

| | 역할 | 사용법 |
|---|---|---|
| `note_vector_map` | 데이터 + 순회 대상 | `.items()`로 돈다 |
| `question_vector_map` | **조회 테이블** | 안 돈다. `[키]`로 꺼낸다 |

`dict`를 "순회하는 것"으로만 생각하면 이 실수가 나온다. dict의 본래 강점은 **키로 O(1) 조회**다.

두 루프의 대상이 비대칭인 게 **맞다** — 노트는 라벨이 없고 질문은 있으니까.

**주의** — `question_vector_map[pair["question"]]`은 질문 문자열이 유일하다는 전제. 중복되면 dict에서 덮어써져 **조용히 잘못된 벡터**를 쓴다.

### ⑥⑦ `summarize()` / 시각화

**방어 코드를 넣은 것**
```python
relevant_min = relevant_scores.min() if not relevant_scores.empty else float('nan')
```

전체 df에선 관련 쌍이 25개라 안 비지만, `kind`별로 자르면 `정답없음` 3개는 관련 쌍이 **0개**가 된다.

**시각화에서 틀린 것 — `bins=30`**

```python
ax.hist(relevant_scores,   bins=30, ...)   # 25개
ax.hist(irrelevant_scores, bins=30, ...)   # 415개
```

`bins=30`은 "**각자의 데이터 범위를** 30등분"이다. 두 데이터의 최소·최대가 다르니 **막대 경계가 서로 다른 히스토그램 두 개**가 겹쳐 그려진다.

→ 비교하려고 겹쳐 그리는데 **비교 기준이 다르다.**

```python
bins = np.linspace(0, 1, 41)   # 공통 구간으로 고정
ax.set_xlim(0, 1)              # subplot 간 비교도 가능해짐
```

**그 밖에**
- 한글: `plt.rcParams["font.family"] = "NanumGothic"` + `axes.unicode_minus = False`
  (한글 폰트엔 유니코드 마이너스 글리프가 없다)
- 기준선은 **주석이지 데이터가 아니다** → 빨강 대신 회색(`"0.3"`). 색은 시리즈 정체성에만.
- 축 라벨은 바깥쪽 한 번만, 범례도 한 번만. 4번 반복하면 잉크만 는다.

## 4. 판단보류 — 결론을 단정하지 않는 이유

**① 표본이 25개** — A와 B의 차이(0.103 vs 0.128)가 실제인지 우연인지 단정 불가.

**② 교란 변수** — 이번엔 노트 **본문 전체**(최대 47,813자)를 문서로 임베딩했다. 그런데 실제 코드는 **요약**을 임베딩한다(small-to-big).

즉 지금 말할 수 있는 건 **"긴 원문을 통째로 임베딩할 때는 분기가 도움이 안 된다"**까지다. 실험③에서 갈릴 문제.

**③ 라벨 검증 미완** — 무관최고 0.746이 유사노트 쌍(`MSA/모놀리식` 등)이면 **라벨 문제지 검색 문제가 아니다.** 확인 전까지 위 숫자는 잠정.

## 6. 메타 — 이번에 배운 작업 방식

**임계값 튜닝에는 천장이 있다.** 네 조합 모두 겹침 True. 어떤 값을 골라도 한쪽 오류는 남는다.

| 손잡이 | 성격 | 효과 |
|---|---|---|
| 임계값 | 수치 튜닝 | 오류 교환 비율만 조정. **분리도 불변** |
| `task_type` | 수치 튜닝 | 0.078 ~ 0.128 |
| 무엇을 임베딩할까 | **구조 변경** | 미측정 |
| 청킹 | **구조 변경** | 미측정 |

**순서**: 라벨 검증 → 구조 개선 → 그 위에서 임계값 튜닝.
잘못된 정답지 위에서 튜닝하면 잘못된 값에 수렴한다.

**실패 기록을 지우지 않는다.** 위의 `dot.product`, `bins=30`, 루프 대상 실수 — 전부 실행 전에는 그럴듯해 보였다. 지나고 나면 왜 그럴듯해 보였는지를 잊어버려서, 그때 안 적으면 영영 못 적는다.
